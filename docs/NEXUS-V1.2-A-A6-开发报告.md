## 二、开发前经济系统审计

### 2.1 当前结构

- 货币：`rewards.credits`（贡献点），唯一货币；信任度 `trust` 不参与交易。
- 经验：`player.exp`，等级 `player.level` 单独存储（不随经验自动推导）。
- 等级表：`LEVEL_XP = [0,100,260,470,730,1040,1400,1810,2270,2780]`（10 级，逐级门槛 100/160/210/260/310/360/410/460/510）。
- 奖励规则集中在 `game/economy.ts`（等级奖励、Boss 首杀、难度奖励、等级解锁、章节结算），但倍率仍是函数内硬编码常量。
- 商店：`game/shop.ts` 22 件商品（A5），价格、限购、库存、交易记录集中在目录与 `shopTx`。
- 会话与结算：A4 `challengeSession` + `completeLevel` 单次结算；A5 购买写 `transactions`。

### 2.2 货币与经验获取途径

| 途径 | 规则 |
|---|---|
| 普通关卡首通 | 基础 `max(15, 关卡经验/3)` + 首通 30 + 零失误 10 + 未用提示 10 + 评级 20/12/6；经验 = 关卡 `rewardExp` |
| 普通关卡重复 | 仅星级提升补偿 6/星（最多 2 星，≤12）；经验 0 |
| Boss 首杀 | 章节奖励 120/150/180/220/260/360（含道具/称号），经验 150–600 |
| Boss 难度奖励 | Hard：+40% 经验、+50% 贡献点；Expert：+70% / +100%（每个 Boss×难度仅一次） |
| 章节奖励 | 40/60/80/100/120/300（一次性） |
| 等级解锁 | 5/7/10 级外观（无货币） |
| 特殊事件/成就 | 无货币产出（仅叙事/外观/知识） |

### 2.3 货币与经验消耗途径

| 途径 | 现状 |
|---|---|
| 兑换中心 | 22 件，单件总价 2785（A5 后） |
| 道具使用 | 消耗库存，不额外收费 |
| 装备/外观 | 一次性购买，无强化费用 |
| 复活/恢复 | 无收费复活；重生恢复 70% 意识，不扣贡献点 |
| 其他 | 无交易税、无修理费、无抽卡 |

### 2.4 修改前数值

- 全流程关卡首通贡献点：**3147**；章节：700；Boss：1290；合计 **5137**。
- 全流程经验：关卡 2930 + Boss 2710 = **5640**；满级门槛 2780。
- 商店单件总价：**2785**（收入覆盖 1.84 倍）。
- 首通样例（1-1，S 评级）：90 贡献点 + 60 经验。

### 2.5 修改前存在的问题

1. **奖励不可追溯**：只有购买有 `transactions`，关卡/Boss/章节奖励没有流水，无法核对「这笔钱从哪来」。
2. **数值无上限**：手改或异常存档可产生 `1e12`、`Infinity`、负数经验/贡献点，购买校验会溢出或显示异常。
3. **等级与经验可能不一致**：等级单独存储，旧档存在 `level 5 / exp 1040`（实为 Lv6）这类矛盾；A6 前不做推导。
4. **后期货币淤积**：收入 5137 vs 商品总价 2785，满级后无可买；缺少高价位消耗口。
5. **配置散落**：等级奖励倍率写在函数体里，价格带无约束，缺少自动化审计。
6. **重复领取**：已有 `firstTime`/`cleared`/`difficultyRewards`/会话结算四层防护，审计未发现可重复入账的路径；但缺少账本级证据。
7. **刷关**：重复通关 0 收益（仅星级补偿），审计确认无法靠反复进出关卡刷钱。
8. **失败惩罚**：仅意识值，无货币损失；连续失败不会负资产，重生恢复 70%，不存在死锁。

## 五、金币收入与消耗规则（A6 最终）

- **首通**：`max(15, rewardExp/3) + 30 + 10(零失误) + 10(未用提示) + 20/12/6(评级)`；
- **重复**：仅当星级提升，`6 × 星数`，最多 12；否则 0；
- **Boss**：章节 120–360 + 难度加成（Hard +50%、Expert +100% 贡献点），每个难度一次性；
- **章节**：整章通关一次性 40–300；
- **消耗**：兑换中心 22 件（20–420），道具使用消耗库存；无修理/复活收费；
- **上限**：贡献点 ≤ 1,000,000；经验 ≤ 10,000,000；信任度 ≤ 100；账本 ≤ 80 条；
- **不做的事**：不新增第二货币、不新增抽卡/强化/手续费、不改判题奖励条件。

收入/消耗总量（全流程一次）：

| 来源 | 贡献点 | 经验 |
|---|---|---|
| 31 个关卡首通 | 3147 | 2930 |
| 6 个章节奖励 | 700 | — |
| 6 个 Boss 首杀 | 1290 | 2710 |
| **合计** | **5137** | **5640** |
| 商店全买一遍 | 2785 | — |

## 六、经验与等级公式

- 保持既有 10 级曲线：`LEVEL_XP = [0,100,260,470,730,1040,1400,1810,2270,2780]`；
- 逐级门槛：100 / 160 / 210 / 260 / 310 / 360 / 410 / 460 / 510（首级 100，末级 510，单级增长倍率 5.1）；
- 自检（`auditLevelCurve`）：单调递增、首级 ≤150、末级 ≤4000、单级增长倍率 ≤8，全部通过；
- 选择「保持曲线 + 收口经验来源」而不是拉平曲线：当前全流程经验 5640 ≈ 2 倍满级门槛，正常玩家在终章前后满级，既不提前封顶，也不形成经验墙；
- 经验只由 `completeLevel` 的真实首通发放；重复通关、失败提交、诊断/运行均不发放；
- A5 经验增幅（×1.5，最多 3 次）已在 `completeLevel` 中接入并在结算显示；
- 等级收益：Lv5/7/10 解锁称号/头像框/粒子；容错仍按 A4 的 `toleranceFor(level)`，未改动。

## 八、失败惩罚调整

- 复核后**不新增**扣贡献点或收费复活：现有设计（意识 -30、归零重生恢复 70%）已满足「有代价但不死锁」；
- 失败提交不扣贡献点、不扣经验，只增加本关失误与会话 errors；
- 连续失败不会产生负资产；重生后本关容错清零（A4 已修），不会立刻再次触发攻击；
- 失败结算仍由 A4 `challengeSession` 写入，UI 展示原因/容错/资源损失，未新增第二套计数；
- UI 上失败结算的「资源损失」仅显示意识，不虚构货币损失。

## 九、反刷机制与漏洞修复

| 风险 | 处理 |
|---|---|
| 重复点击通关 | A4 在途锁 + 会话已结算直接返回 `null` |
| 刷新重复领取 | 会话状态持久化；`completeLevel` 对 `passed` 会话拒绝二次结算 |
| 重复 `completeLevel` | 账本 `level:<id>` 一次性去重 + `cleared` + 会话三层 |
| 重复进入结算页 | 奖励只在 `completeLevel` 内发放，打开面板不触发 |
| 低难度无限刷 | 重复通关 0 收益；模拟 50 次刷 1-1 收益为 0 |
| 退出挑战拿奖励 | 奖励仅由真实判题通过触发 |
| 经验增幅无限叠 | A5 限购 3 + 使用上限 3 + 结算消耗 |
| 前端改价/负数/超大数量 | A5 `purchaseItem` 重新校验目录价格与数量 |
| 异常存档负数/NaN/超大 | 迁移与载入 `safeCredits/safeExp` 夹取；账本/交易/增益全部规范化 |
| 重复交易 | A5 `requestId` 去重 |
| 奖励不可追溯 | 新增账本：`kind/ref/credits/exp/at` + 唯一 `id` |

**安全边界（如实说明）**：本项目是纯前端 + localStorage 单机存档。上述校验能防止 UI 误操作、重复请求、异常数据与前端参数篡改；但无法阻止玩家直接编辑 localStorage 伪造货币/经验。真正的服务端防作弊需要在后端重算奖励与库存，本项目不声称具备该能力。

## 十一、存档迁移方案（v9 → v10）

- 只做增量，不覆盖任何既有字段：
  1. `rewards = normalizeRewards(rewards)`：补齐 `ledger`，清洗交易/限购/增益，贡献点夹取；
  2. `exp = safeExp(exp)`；载入时 `level = levelForExp(exp)`（修复历史矛盾）；
- 账本初始化不影响已有 `cleared/chapterRewards/difficultyRewards/bossesDone`；
- 迁移幂等：重复执行不会重复发奖（账本只补默认空数组，不生成流水）；
- v1–v9 迁移链保持不变，v10 追加在末尾；
- 迁移前后对照测试：`session_check`（会话字段）、`economy_check`（账本/夹取）、`identity_e2e`（旧档迁移）、`settlement_e2e`（v7→v10）。

## 十四、已知问题与剩余风险

1. **客户端安全边界**：单机 localStorage 存档无法防直接改档；已在报告中如实说明，不声称服务端防作弊。
2. **经验上限后无消耗口**：满级后经验仍会累积但不再影响等级（上限 10,000,000 夹取）；这是等级上限设计的自然结果。
3. **账本容量 80 条**：长期游玩后早期流水会被裁剪；一次性奖励仍以防重复字段为准，不影响正确性。
4. **奖励账本未覆盖 A5 购买**：购买继续由 `transactions` 记录，二者职责分离（收入 vs 支出），未合并成单一流水表。
5. **失败不扣货币**：按需求「没有收费复活就不要强行添加」，保留现状；若未来加入服务端经济，可在此扩展。
6. **价格平衡基于单人全流程模拟**：没有真实玩家数据，数值以「收入覆盖 1.84 倍、重复收益 0」为约束，后续可根据实机数据微调。
