## 一、本增量目标与范围

按负责人指令「先完成独立挑战模板和测试，再选择少量关卡验证，确保原有游戏内容不被破坏」，本增量只交付：

1. 与判题 / 诊断 / 事件 / 结算解耦的统一挑战规则层（`challengeRules`）；
2. 挑战运行状态机与资源 / 限时 / 连锁 / 多阶段执行层（`challengeEngine`）；
3. 五种挑战类型的模板构建器（`challengeTypes`）；
4. 五个与 31 个原有关卡完全解耦的独立示例挑战（`challengeTemplates`，`ind-` 前缀）；
5. 纯逻辑单元测试（`test/challenge_engine_check.mjs`）。

本增量**不**做：UI 接入、存档持久化、原有关卡改造、真实 MicroPython 运行样例。原有关卡在本阶段保持原样。

> 过程说明：本机未安装 codex CLI（`codex: command not found`），上述工作由助手在本会话内直接完成并验证，未通过 codex exec 委托执行。

| 全量冒烟 | `node test/smoke.mjs` | **全部通过** |

测试覆盖点（`challenge_engine_check.mjs`）：

- 规则校验：空配置 / 非法难度 / 非法类型 / 负次数 / 非法时间 / 奖励系数封顶 / 限时缺时间默认 120 秒 / 极端配置不抛异常 / 难度预设。
- 状态机：创建即进行中并设截止时间、暂停/恢复/顺延截止、结算幂等、非进行中操作无副作用。
- 资源消耗：运行/提交/提示封顶到上限、剩余不为负、超限不可再用、`maxHints=0` 不可提示、不限次时剩余为 `null`。
- 限时：按时间戳差值算剩余、到达截止判超时、已结算不再判超时。
- 连锁 Bug：依赖未修复不可修后续、依赖满足后全量完成。
- 多阶段：初始第 1 阶段、不允许跳阶段、全部完成后视为完成。
- 隐藏测试：初始未判定、全部通过后视为通过。
- 序列化自愈：往返保持关键字段、脏数据归零、空状态丢弃。
- 模板：5 个模板规则自洽无 issue、字段完整、类型全覆盖、隐藏/连锁/限时字段正确。
